# 贡献与维护指南

## 新增一篇内容

1. 先判断内容属于基础知识、技术模块、课程、项目、经验或交接。
2. 原始文献、厂商手册、网页摘录等放入 `sources/`，保留来源信息；不要把版权受限文档直接公开提交。
3. 按 `templates/` 中对应模板新建 Markdown。将事实、个人经验、推测和待验证事项区分开。
4. 引用原始来源或记录实测环境、日期和验证方法；更新 `wiki/index.md` 与 `wiki/log.md`。
5. 检查相关页面的链接与目录，并在 `docs/` 中加入导航（如果是面向读者的正式页面）。
6. 提交 Pull Request，由成员检查准确性、可复现性和公开资料许可后合并。

## LLM Wiki 维护约定

- 原始资料是证据层；归纳页不是原始资料的替代品。
- 助手可以提出页面改动，但来源、数字、版本、命令和实验结论必须由成员核实。
- 新来源可能修正旧结论时，注明变化、日期和依据，并检查依赖旧结论的页面。
- 有价值的问答总结可以沉淀成知识页，附来源与适用范围。
- 定期检查断链、孤立页、过时版本、来源缺失和冲突。

## 本地预览

```bash
python -m pip install -r requirements.txt
mkdocs serve
```

## 提交前检查

```bash
mkdocs build --strict
```

确认侧边栏可到达新文档，代码命令中的路径与版本已核对，图片和附件可访问。
